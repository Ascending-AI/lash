## Finding-to-fix and regression map

1. **Resumable Restate starts.** Post-registration workflow-submission and
   external-reference failures now retain staging inputs; cleanup happens only
   on authoritative abandonment. Deterministic injection covers registration,
   submission, external-ref failure, and recovery in
   `restate_start_failures_preserve_inputs_for_exact_recovery`.
2. **Production dependency wiring.** `LashCore` retains the host process-engine
   registry separately from session-scoped engines and passes the exact bound
   environment store/engines through facade, tool-intent, trigger, and session
   start paths. `host_owned_processes_run_without_application_session` and
   `session_trigger_process_visibility_conformance` exercise real controllers.
3. **Public replay.** Public session/facade starts carry the environment spec
   into the replayable effect and no longer republish through a retired staging
   owner. Existing process ownership is discovered/transferred idempotently.
   `process_start_and_cancel_emit_typed_observation_events` and the host-owned
   process test both repeat public starts after staging retirement.
4. **Recoverable process-prune cleanup.** `ProcessArtifactCleanup` is recorded
   transactionally with prune/tombstone state and acknowledged only after exact
   environment and engine-family release. Trait decorators forward the new
   APIs. In-memory, SQLite-reopen, PostgreSQL-reopen, and facade fault-injection
   tests preserve a shared owner and retry after each artifact family fails.
5. **Complete execution-owner cleanup.** Existing
   `effect_scope_retirements` rows now carry `artifact_cleanup_completed`.
   Session deletion plus immediate/deferred operation retirement enumerate
   pending scopes, permanently retire each configured artifact store, then ack.
   Immediate facade errors are returned. SQLite reopen injection fails once at
   each environment/module store; PostgreSQL/SQLite effect-journal tests prove
   pending/ack state, and the seven-test runtime-operation suite proves facade
   and deferred-sweep behavior.
6. **Real slow-writer evidence.** `ArtifactPublicationPause` is consumed inside
   memory, SQLite, and PostgreSQL publication before the serialized mutation;
   conformance starts a writer, observes the pause, commits retirement, resumes
   it, and requires typed refusal with no resurrected bytes/edge.
7. **PostgreSQL artifact serialization.** Every publish, retain, transfer,
   release, and retirement takes a stable advisory lock keyed by
   `(namespace, artifact_ref)` after ordered owner locks. Real PostgreSQL 16
   tests deterministically hold that exact key and prove a committed B owner
   survives A release, concurrent final releases remove bytes, and retirement
   fences a late publisher. The first race waits until `pg_stat_activity`
   proves release reached its serialization point, eliminating scheduler
   false-greens.
8. **Cross-store retirement recovery.** The same durable pending/ack evidence
   from item 5 survives reopen until every store succeeds. The recovery test
   additionally proves the authoritative journal fence immediately rejects a
   late runtime effect, and completed cleanup rejects late environment and
   module publication.

SQLite process/effect schemas advance `32 -> 33` and `17 -> 18`; PostgreSQL
advances `86 -> 87`. The committed PostgreSQL shape, schema-congruence registry,
retention census, and ADR 0093 are updated. No compatibility, refcount, lease,
heuristic, second lifecycle journal, or FIG-2875 dependency was added.

## Red-side negative controls

Every mutation below was applied alone, produced the intended oracle failure,
and was restored before the green runs.

1. Restored eager staging retirement on Restate scheduling failure, then ran
   `. ./env.sh && cargo test -p lash-internal-restate restate_start_failures_preserve_inputs_for_exact_recovery -- --nocapture`
   — FAILED: `a retriable workflow failure must not reclaim the committed process input`.
2. Passed the empty session engine registry to facade process administration,
   then ran `. ./env.sh && cargo test -p lash-runtime --features rlm host_owned_processes_run_without_application_session -- --nocapture`
   — FAILED: engine `lashlang` was not configured.
3. Restored prepublication under the public replay staging owner, then ran
   `. ./env.sh && cargo test -p lash-runtime process_start_and_cancel_emit_typed_observation_events -- --nocapture`
   — FAILED on replay: `artifact owner has been permanently retired`.
4. Removed pending/ack forwarding from the process-registry decorator, then ran
   `. ./env.sh && cargo test -p lash-runtime --features rlm process_prune_retries_each_artifact_release_after_registry_reopen -- --nocapture`
   — FAILED: prune incorrectly returned success while exact cleanup evidence
   and the injected failure remained untouched.
5. Changed SQLite pending-retirement selection from
   `artifact_cleanup_completed = 0` to `= 1`, then ran
   `. ./env.sh && cargo test -p lash-internal-sqlite-store scope_retirement_retries_each_artifact_store_after_reopen -- --nocapture`
   — FAILED before the injected artifact-store error because recovery enumerated
   no pending lifecycle evidence.
6. Removed the retired-owner check after the memory-store publication pause,
   then ran `. ./env.sh && cargo test -p lash-internal-lashlang in_memory_lashlang_artifact_store_satisfies_conformance -- --nocapture`
   — FAILED: `retirement must fence a late writer`.
7. Replaced PostgreSQL `lock_artifact` with a no-op, then ran
   `. ./env.sh && LASH_POSTGRES_DATABASE_URL=postgresql://postgres:lash@127.0.0.1:33228/lash LASH_REQUIRE_POSTGRES=1 cargo test -p lash-internal-postgres-store --test conformance postgres_artifact_release_observes_owner_that_commits_ahead_of_it -- --nocapture`
   — FAILED: `the owner that committed ahead of release must keep the bytes live`.

An initial version of negative control 7 only yielded once before releasing the
blocking transaction and false-greened under the no-op mutation. The persistent
test was tightened to observe the actual PostgreSQL wait state; the restored
lock then passed and the same no-op mutation failed deterministically.

## Risks, limits, and review readiness

- Findings 1-4, 6, and 7 are fully proven by direct deterministic regressions
  on every relevant path/backend named by the finding.
- Findings 5 and 8 are proven with one explicit backend-composition limit:
  injected fail/reopen at both artifact families uses a durable SQLite effect
  journal, durable SQLite module store, and in-memory environment store.
  PostgreSQL pending/ack durability, runtime sweeps, artifact conformance, and
  concurrency are proven separately on PostgreSQL 16; no PostgreSQL
  cross-store fault/reopen Cartesian duplicate was added.
- The branch was fetched but deliberately not rebased: before the remediation
  commit it was 1 commit ahead / 8 commits behind `origin/main`. Local checks
  pass on branch lineage; the PR merge ref remains the authoritative current-main
  integration proof.
- Six compiler-directed edits outside the ownership modules (four `Box::pin`
  sites and two private type aliases) are mechanical Clippy fallout from the
  larger async start future. Focused module extractions and historical
  version-bump fixture synchronization were also required by repository
  pre-commit gates; none changes protocol or lifecycle semantics.

Behavior/contracts re-review should focus on Restate resumability, host/facade/
trigger dependency identity, public replay, and cleanup error propagation.
Durability/concurrency/failure-path re-review should focus on transactionally
retained prune evidence, the reused scope-retirement pending/ack state machine,
stable PostgreSQL artifact locks and lock ordering, and the red/green schedules
above.
