# FIG-7647: Tool-intent submission lifecycle is private

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `lash::tools::ToolIntentSubmissionRecord` had public `intent: ToolIntentSubmissionPayload` and `settlement: Option<ToolIntentSubmissionSettlement>` fields. | The lifecycle (pending, settled, expired) is private. Read the payload with `intent() -> Option<&ToolIntent>` (`None` once expired) and the first settlement with `settlement() -> Option<&ToolIntentSubmissionSettlement>`. Only `complete` settles a row; only decoding a row whose payload the store cleared yields an expired one. | This commit, FIG-7647 | Rust reports private fields `intent` and `settlement`. |
| `lash::tools::ToolIntentSubmissionPayload` was exported. | Removed. Match on `record.intent()` instead of `Retained`/`Expired`. | This commit, FIG-7647 | Rust reports an unresolved import. |
| `ToolIntentSubmissionRecord::complete(&mut self, at_ms, outcome) -> Result<bool, PluginError>`. | `complete(self, at_ms, outcome) -> Result<StoreTransition<ToolIntentSubmissionRecord>, PluginError>`: it consumes the row and returns it with `changed`. A registry persists `ledger_columns()?.settlement_json` when `changed`. | This commit, FIG-7647 | Rust reports a mismatched receiver or return type. |
| `ToolIntentSubmissionRecord::validate_settlement()` was public. | Removed: a settlement can only enter a row through `complete` or validated decoding, so there is nothing left to re-check. | This commit, FIG-7647 | Rust reports no method `validate_settlement`. |

The wire shape, ledger columns and SQL schema are unchanged; stored rows need no reset.
