# FIG-7523: Explicit helper upgrades

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| Publications and runs keep exact helper hashes with no owner upgrade operation | With `codemode`, call `HostArtifacts::upgrade_publication` for a linked revision or `upgrade_definition` for a linked or captured process definition. Review the returned helper diff and choose the host alias explicitly. Previous revisions remain retained under their existing pins. | This commit, FIG-7523 | Saved code continues on its archived helpers until the host requests an upgrade. |
| Process succession is identified only by its selected pair | `Processes::upgrade_run` takes a host pin and `HelperRunUpgradeRequest { request_id }`. The fenced owner rechecks saved callables, frames, continuations, tasks, completions, start arguments and branded constructor stamps. Draining state remains pending; permanent code and branded data refuse typed. Read the existing successor event to observe asynchronous settlement. Runs never opt in automatically. | This commit, FIG-7523 | `HelperContractChanged`, `HelperTombstoned`, `RetainedCallable` or `BrandedData`; a pending active continuation continues on old code. |
| `ProcessSuccessor` and persisted `ProcessSuccessorRequest` have no request id | The new optional `request_id` defaults to absent through `ProcessSuccessor::new`. A repeated id returns `AlreadyResolved` when its event exists and the owner acknowledges any duplicate without switching again. Requests with ids settle in mailbox order; later requests cannot displace an unsettled id. No new configuration is required for ordinary succession. Captured publications preserve safe frozen data while rewriting their selected callable. Nested callables and branded data that reach changed bodies refuse typed. A settled request id returns no new publication. The result's `from` and `to` are `WorkflowReference`, naming either a linked start or a callable. | This commit, FIG-7523 | Hosts constructing the structs directly must initialize `request_id` and initialize a recorded request's `unchanged` to false. The fenced owner stamps `unchanged` on a no-op settlement; its event reserves the id without resetting workflow counts. |
