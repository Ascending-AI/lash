# FIG-7525: Inspect logical native resource contracts

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `workflow::document::NativeFunction` exposes execution and specialization methods. | It also exposes `resource_contract(&self, Args<'_>) -> Result<Option<NativeResourceContract>, NativeError>`. Existing implementations inherit `Ok(None)`. Hosts supplying checked native resource descriptions override this input-only query. No new build feature or configuration is required. | This commit, FIG-7525 | An implementation using the default has no certified resource description. `None` must remain uncertified rather than becoming a zero-cost contract. |
| The workflow document facade has no native resource vocabulary. | Hosts can name `NativeResourceContract`, `NativeResourceEntity`, `NativeResourceEvent`, `NativeResourceExit`, `NativeResourceHolding`, `NativeResourceOrigin`, `NativeResourceOwner` and `NativeResourceRelease` through `lash::workflow::document`. No new opt-in is required. | This commit, FIG-7525 | Hosts compiling these imports against an earlier revision get unresolved-import errors. |

The query describes logical obligations. Guest memory admission continues to use the existing metric.
