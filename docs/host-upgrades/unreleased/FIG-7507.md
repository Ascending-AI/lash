# FIG-7507: Reset stores with unstamped kernel token bodies

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `KERNEL_DOCUMENT_SCHEMA_VERSION = 1` did not track token-codec changes. In `49dd61b4f9`, `FunctionDefinition` grew from seven to eight fields without changing the witness. | `KERNEL_DOCUMENT_SCHEMA_VERSION = 2` identifies the current token encoding, independently of semantic kernel version 1. Hosts comparing durable-format witnesses now observe a format change. Reset stores written before `49dd61b4f9` before deployment. Eight-field function bodies written after that commit retain their identities; unstamped document bodies require recreation. No migration or old-body decoder is provided. | This commit, FIG-7507 | Previously, the upgrade survey could report `durable_format_change=false`, followed by `non-canonical body: expected 8 fields, found 7`. Preflight now reports encoding 1 as refused against expected encoding 2. |
| `DOCUMENT_GRAMMAR_VERSION = 1`; document bodies had no encoding stamp. | Grammar 2 stamps document bodies. Function bodies retain the eight-field encoding introduced by `49dd61b4f9`; preflight distinguishes it from the old seven-field format by arity. Recreate retained `DocumentBytes` and pre-`49dd61b4f9` function declarations from typed source; old opaque document bodies and their identities are not reusable. No feature or configuration opt-in is needed. | This commit, FIG-7507 | An old opaque grammar is refused at receipt, and an old body is refused before semantic admission. |

The preflight only reads version evidence from old framing; it never decodes
an old definition. A streamed artifact whose witness requires child reads
remains explicitly undecidable in the bounded probe.
