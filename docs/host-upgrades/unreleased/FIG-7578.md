# FIG-7578: Admit MCP tools individually

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| One unusable schema failed server startup or retained the previous catalog on refresh. `McpError::UnusableSchema` and `McpServerFault::UnusableSchema` carried that failure. | Admitted tools publish on startup and refresh. A newly refused tool leaves the catalog; a repaired tool returns. Remove matches on the deleted variants and read `McpServerStatus.tool_refusals`, a map of native tool names to `SchemaAdmissionError`, from the pool or plugin's existing `server_statuses()`. No opt-in. | This commit, FIG-7578 | Removed-variant compiler errors; old status decoders must accept `tool_refusals`. A connected server can publish fewer tools with typed refusals. |
| The workbench MCP server response carried names, connection state and tools; startup logged server errors. | Responses also carry `tool_refusals`; startup logs each refused tool and its reason. | This commit, FIG-7578 | Refused tools appear beside admitted tools in server diagnostics. |
