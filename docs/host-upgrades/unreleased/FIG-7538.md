# Notification-source acquisition failures reach the host

`subscribe_and_recover` now yields `Err(EmbedError::Durable(cause))` and ends
when it needs a backend notification observer and that observer cannot open.
This applies when `AfterCommit` notifications select a store's node-wake
transport, including PostgreSQL and SQLite file stores. The error preserves
the transport's typed `DurableError` cause. The failed acquisition is logged
once with the store and session.

The host handles the cause and creates a new `subscribe_and_recover` stream
from its last applied cursor. A failed acquisition consumes no cursor. The
stream performs no internal retry, timed polling, or local-only fallback.
Existing replay gaps still carry the authoritative replacement observation.

SQLite memory stores intentionally have no node-wake transport and continue
to deliver same-process commits. Send followers retain their polling
fallback when observer acquisition fails.

No enum variant was added, so exhaustive stream/error matches do not change.
Store adapters using `WakeSink::observe` must now handle its
`Result<KeyWatch, DurableError>`: no transport returns a local watch, while a
failed transport returns its error. A caller with an existing polling
fallback can choose that fallback explicitly.
