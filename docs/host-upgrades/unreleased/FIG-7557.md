# FIG-7557: Retain bound facts and saved read identity at host boundaries

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `ToolCallRecord` omitted whether a call was a read and its caller identity | Records carry `execution` and optional `read: ToolReadIdentity`, retaining caller, ordinal, provider, site and origin. Update record constructors and host storage decoders. Correlate saved and live reads by caller and ordinal. | This commit, FIG-7557 | Old constructors fail to compile; host DTOs that discard these fields cannot correlate model read history. |
| Process saved reads required an already known call id | `Processes::saved_reads` lists retained reads in ordinal order as `ToolCallRecord` values, including for terminal processes after live replay expires. It performs no execution. | This commit, FIG-7557 | A terminal run's read rows disappear if the host consults only live replay. |
| Worker limits and fresh cell ends could lose structured bound evidence | Worker and kernel failures use the shared bound constructor. `CellResource::WorkerDeadlineNanos` identifies a worker exchange deadline whose compute/serialization phase is unknown. Saved cell ends retain their normalized fact across takeover; missing receipts remain absent. No opt-in is required. | This commit, FIG-7557 | Parsing failure text misses structured evidence, and filling absent receipts with zero invents measurements. |
| A root process trace terminal had no typed failure | `TraceDomainCompletion.failure` and language `ExecutionFinished.failure` carry the terminal classification and structured bound. Cell, process and workflow spans use the same `lash.execution.bound.*` attributes. No content opt-in is required for bound facts; diagnostic content keeps its existing policy. | This commit, FIG-7557 | A host enricher that inspects only tool-return events misses root process bounds. |
