# FIG-7700: Automatic format witnesses

## Read a process's whole stored environment

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| Stored environments have a head, a shared content-addressed body and a separate module closure. No artifact row is a whole `ProcessEnv`; table layout is private. | Use `HostArtifacts::get_process_env(&ProcessId) -> Result<Option<ProcessEnv>>` to read the exact environment the process started under. No new opt-in is required. The returned value can be passed to `link_process_env` with the existing `codemode` feature. | This commit, FIG-7700 | Decoding individual artifact rows with `ProcessEnv::from_store_bytes` fails or loses the shared body. |

The read returns `None` for an unknown or pruned process, a session-turn
process with no engine environment, or an environment no longer stored.
Corrupt or undecodable stored bytes remain an error. It is an uncached
snapshot that takes no lock or lasting hold and reads no referrer edges.
PostgreSQL uses one statement and one round trip.

Normal completion retains the environment head under the process record until
prune, even after the execution's cleanup runs. The head keeps the shared body.
If the record's environment share is also ended, the read keeps answering
while another holder, such as the publisher's pin, holds that head. It returns
`None` once the last head holder ends. Ending a module share alone does not
end the head's lifetime. This read changes no retention.

Source: [host artifacts](../../../crates/lash/src/artifacts.rs),
[process authority reader](../../../crates/lash-postgres-store/src/postgres/process_registry.rs),
[split environment lifetime](../../../crates/lash-core-store/src/process_env_stored.rs).

## Bounded waits after artifact locks

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| A PostgreSQL transaction holding artifact locks waits on later locks without a bound; a lock cycle ends only through PostgreSQL's deadlock detector. | After its artifact locks, a transaction waits at most `guards.sealed_lock_timeout_ms` (default 250 ms) for a row and does not wait for an advisory lock; the store retries the whole transaction. A wait that expires after the artifact locks does not use up one of the operation's attempts: the operation keeps retrying a held row until its own deadline, then answers contention. `PostgresStorage::connect` refuses a configuration whose sealed lock timeout is not below the server's `deadlock_timeout`, so a default Lash refuses to open against a server whose `deadlock_timeout` is 250 ms or less. Keep `deadlock_timeout` above the sealed timeout, or lower `guards.sealed_lock_timeout_ms`. | This commit, FIG-7700 | `PostgresHostError::SealedLockTimeoutNotBelowDeadlockTimeout` at open. |

Source: [guard policies](../../../crates/lash-postgres-store/src/host/config.rs),
[open check](../../../crates/lash-postgres-store/src/lib.rs),
[sealed lock](../../../crates/lash-postgres-store/src/postgres/advisory_lock.rs).
