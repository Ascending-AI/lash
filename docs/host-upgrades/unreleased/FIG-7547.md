| Cell and workflow Read operations had no general host tool activity | Handle the existing `ToolCallStarted` / `ToolCallReturned` family with `execution: read` and optional `read: ToolReadMetadata`. Processes carry those same events in `ProcessObservationEventPayload::Activity { event_key, event }`. The metadata carries caller/provider, ordinal, site/origin, elapsed time and byte sizes. The ordinary return output carries success or failure. Read ids derive from caller plus ordinal; reads never emit `ToolCallCompleted`. No new opt-in. These rows are provisional; correlate by caller plus ordinal and reset on gaps. No per-read committed history exists. | This commit, FIG-7547 | Rust constructors need `execution` and `read`; exhaustive process-feed matches need the Activity envelope. | `plugins::ProcessComposition::effect_reads(env, clock)` | Also pass the process id and its optional live tool-event callback.
