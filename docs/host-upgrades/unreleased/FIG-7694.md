A missing SQLite path passed to `SqliteStoreSet::open_existing_readonly`,
including through `deployment-status`, `stalled list`, `kernel-migration list`
or `stranded list`, now returns `StoreError::Incompatible` with the existing
`CompatRefusal::Unstamped` variant. JSON reports `incompatible_store`, exit 4,
and `{"refusal":"unstamped","component":"sqlite-core"}`; no file is created.
This replaces `unexpected_failure`, exit 1, and `refusal: null`. It adds no
serialized shape or public error variant, so no format version moves.
For an `unstamped` refusal, check the location and use `lashctl preflight` for
PostgreSQL or the host's `verify_schema_at` for SQLite. Exit 4 alone authorizes
no deletion; this wording change adds no format or API change.

## Exhausted-park classification uses its recorded code

`lash::persistence::ParkReason::stopped_behind_unsettled_redrive` now reads
`EngineRetryExhausted.last_failure_code` only. This intentionally corrects the
previous message search; it does not preserve its answers for every park a
host can construct. A missing or different code answers false even when the
message contains `session_redrive_unsettled` or `SessionRedriveUnsettled`.
The correct code answers true even when the message is empty or unrelated.

A host constructing `EngineRetryExhausted`, directly or through
`ParkReason::engine_retry_exhausted`, supplies the failure's wire code in
`last_failure_code`. For this refusal use
`Some(RuntimeErrorCode::SessionRedriveUnsettled.as_str().to_string())`.
The message is display text and carries no classification authority. There
is no text fallback and no stored-shape change. The switch resets old stores.

## Switching from the retired build

The new build refuses old stores at open. It cannot inspect or settle their
started calls. Do the following on the old build before resetting a store.

1. Stop admission in the host, including external dispatch. Prevent old nodes
   and workers from restarting throughout the switch.
2. Inventory calls without an outcome, using the old store. Main at
   `d709cfaf7f` has no `lashctl` command to list or settle them.

   ```sh
   sqlite3 -readonly "$LASH_SQLITE_PATH" \
     'SELECT owner_key, call_id, decision FROM tool_calls WHERE answer_outcome IS NULL ORDER BY 1, 2'
   psql "$LASH_POSTGRES_DATABASE_URL" -At -c \
     'SELECT owner_key, call_id, decision FROM lash_tool_calls WHERE answer_outcome IS NULL ORDER BY 1, 2'
   ```

3. Use an old-build host node to resume interrupted turns. A started `Once`
   settles as `Interrupted` without re-executing its body. Cancel parked
   processes through `LashCore::processes().cancel(OperationId::mint(), &id)`.
   Wait for the host's `LashCore::drain_status(false)` to report zero
   invocations and turns in flight, then call `LashCore::drain()` and stop
   every old node and writer. Main has no CLI resume or process-cancel verb.
   Before the drain, read status through the host. The old build's
   `lashctl deployment-status` can claim cleanup work; PostgreSQL recovery
   reads, including `stranded list`, create an attachment file in their
   working directory.
4. With all old writers stopped, repeat the SQL inventory. The reset check
   is **no started tool row with neither an outcome nor a cancel decision**.
   The following query must return no rows for the selected backend:

   ```sh
   sqlite3 -readonly "$LASH_SQLITE_PATH" \
     "SELECT owner_key, call_id FROM tool_calls WHERE answer_outcome IS NULL AND (decision IS NULL OR decision <> 'cancel') ORDER BY 1, 2"
   psql "$LASH_POSTGRES_DATABASE_URL" -At -c \
     "SELECT owner_key, call_id FROM lash_tool_calls WHERE answer_outcome IS NULL AND (decision IS NULL OR decision <> 'cancel') ORDER BY 1, 2"
   ```

   A row with `decision='cancel'` and no outcome is allowed only after its
   owning process has ended. The old build leaves such a row for a cancelled
   `sleep`. Never infer that an unrecorded outcome means work did not run.
5. Back up the stopped store, then reset it. For SQLite, remove the selected
   database and its `-wal`, `-shm`, and `-liveness` companions. For PostgreSQL,
   drop and recreate the selected database with the host's administrative
   tooling. After recreation, before any new node starts, provision it with
   the **new build's** operator binary:

   ```sh
   LASH_POSTGRES_DATABASE_URL="$LASH_POSTGRES_DATABASE_URL" "$NEW_LASHCTL" --json migrate
   ```

   This runs the current `bootstrap-<schema-version>` step. SQLite provisions
   a fresh database when the new build opens it.
6. Deploy the new host and VM worker together, start the new nodes, and verify
   a new turn completes before reopening admission. Old session bindings,
   saved functions, and parked runs do not carry across the reset.

A host that wipes its own disposable data together with the Lash store may
skip the call inventory only by explicitly accepting that outstanding
external work is abandoned. It must still stop old writers and ship the
host and worker together.

## Deploy the host and worker together

Ship the Lash host and worker from the same build. The worker protocol advances
from 11 to 12 because checkpoint-start messages and source-service Written
records changed. Protocol 12 refuses a protocol-11 worker before guest admission;
resetting a store does not make mixed host and worker binaries compatible.

## Retained documents and source imports

`DOCUMENT_GRAMMAR_VERSION` and `KERNEL_DOCUMENT_SCHEMA_VERSION` stay at 7.
The executable Document token encoding did not change. Old documents remain
readable when their exact imported helpers and executable definitions remain
installed, including archived helper identities. Preserve those helpers for
host-retained documents and exported workflows; a store reset does not remove
such external bytes. Grammar equality alone does not promise equal resource
observations or helper availability in both builds.

Source printed by this build can use new operation spellings, including
`list.element`, `record.field`, `value.text_join` and `value.null()`. The old
build cannot import source using those spellings or resolve newly introduced
helper identities. Recompiling source can also change its DocumentId when the
compiler emits a smaller helper header. Retain typed documents or source and
qualify representative retained documents against the new build before rollout.
This document claim does not extend to parked state, saved functions, snapshots,
store schemas or host mirrors, whose changed witnesses require the reset or
recreation listed below.

## Call and function count limit of the bytecode core

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| Main's region engine accepts any number of arguments in one call or spawn (statement calls and spawns carry `usize` counts, expression registers `u32`). Before this change the bytecode core wrapped a count of 65,536 or more silently, and a function with more than 65,535 parameters and locals panicked while compiling. | The bytecode core holds at most 65,535 arguments in one call, spawn or effect, and 65,535 parameters, locals and temporaries (and captures) in one function, and 65,535 global names in one program. A document past a limit is refused, never wrapped and never a panic, as one the core cannot compile: `KernelMachine::start` (and `open`) return `StartError::Linked` naming the count and the limit. Publication and linking (`Program::prepare`) still accept such a document. Split the call or function. No opt-in is provided. | This commit, FIG-7694 | `StartError::Linked` "the bytecode core cannot compile this document: 65536 arguments of one call or spawn, more than the bytecode core's limit of 65535". |

Source: [compiler limits](../../../crates/lash-kernel-vm/src/bytecode/compile.rs).

The compiler checks local and temporary allocation before using slot offsets,
including protocol loops. Its shared pools of units, constants, natives,
completion formulas and occurrence sites use indices below 2,147,483,648,
reserving the high bit for library IDs. Bytecode coordinates and derived table
lengths fit `u32`. A completion formula can measure argument positions 0 through
254; position 255 is reserved for the result. A formula naming a later argument
returns `StartError::Linked` with an unsupported-document diagnostic instead of
aliasing another operand. These checks add no opt-in or stored-format change.
