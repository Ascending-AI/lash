# FIG-7640: JSON native versions and host number spelling

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| FIG-7637 changed the refusals of json.render and json.stringify (boundary context, path prefix, key message) under native version 1. | json.render and json.stringify are native version 2 on the shared encoder; version 1 keeps its exact pre-FIG-7637 writer for archived definitions. Helper release 0007 records them. Rebuild/re-admit affected definitions using the normal native adoption process. | This commit, FIG-7640 | An archived definition answered with the new refusal text. |
| Since FIG-7637, `encode_datum` spelled host-copied floats in JavaScript's decimal layout, so a whole float such as `3.0` reached tools as `3.0`. | `encode_datum` spells finite floats as `Float::json_number`: a whole float below 2^53 is a JSON integer and `2**53` stays `9007199254740992.0`, as before FIG-7637. No opt-in is required. | This commit, FIG-7640 | Tools that validate an integer argument refused a whole number. |
| Since FIG-7637, an RLM cell value holding an error read as `{}`. | An error reads as its typed fact `{"$kind":"error","kind","message","data"}`, with `data` from the error's original evidence. | This commit, FIG-7640 | A binding of a caught error lost its kind and message. |
