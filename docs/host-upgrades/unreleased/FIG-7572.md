| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `ToolCallRead` has `Settled`, `NotYetSettled`, and `NotFound` | Handle `SettledWithoutRecord { call_id, outcome: Box<turn::RecordedCallOutcome> }` for a committed terminal with no materialized record. | This commit, FIG-7572 | Exhaustive matches fail to compile; a body-free terminal must not appear pending. |

| Session/cell readers reconstruct calls from replay or transcript state | Existing `DurableSession::{read_tool_call, read_tool_calls, read_cell_tool_calls, read_turn_tool_calls}` retain calls across compaction and turn end. `Processes::saved_reads` lists retained Reads after reopen. No opt-in. | This commit, FIG-7572 | Reads no longer depend on old journal or cell state. |
| Model-call scalar consumers load every call on the turn | `DurableSession::read_model_calls(&[TurnModelCallRef])` selects keys before hydrating bodies; `read_turn_model_calls` lists the turn. No opt-in. | This commit, FIG-7572 | Unrelated model bodies no longer affect keyed reads. |
| Custom `DurableReads` decorators forward owner-wide call reads | Forward `tool_calls`, `model_calls_by_id`, `model_call_pins_by_id`, `model_call_pin`, and `model_call_ids` to the owning store. | This commit, FIG-7572 | Missing trait methods fail to compile; keyed reads have no walking default. |

Tool admissions now carry their running turn count. The separate `TurnWrite::AddToolCalls` operation is removed; caller-saved Reads do not consume that count. Model reservations and sealed records share one lifecycle row.
