# FIG-7651: Helper run upgrades couple outcomes with their publications

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `lash::process::HelperRunUpgrade` exposes independent `state: HelperRunUpgradeState` and `publication: Option<HelperPublicationUpgrade>` fields | Match `outcome: HelperRunUpgradeOutcome`. `Requested { publication }` and `AlreadyCurrent { publication }` require the prepared revision. `AlreadyResolved` has no publication, including when the request settles during preparation. The `request_id` field remains. `HelperRunUpgradeState` is removed. The existing `codemode` feature is required; no new opt-in is required. | This commit, FIG-7651 | Old field access and enum imports fail to compile. A prepared publication is an artifact, not evidence that the fenced owner accepted succession. Observe the process's existing successor events for settlement. |
| `kernel-helper-run-upgrade/v1` JSON and TypeScript declarations use top-level `state` and optional `publication` | Use `kernel-helper-run-upgrade/v2`, stamped by `HELPER_RUN_UPGRADE_VERSION = 2`, exported through `lash::process`. Read `{"request_id":"id","outcome":{"status":"already_resolved"}}`, or an outcome with `status` of `requested` or `already_current` and required `publication`. `HelperRunUpgrade::from_json` rejects old responses with `DecodeError::Invalid`; direct Serde decoding rejects them too. Replace cached v1 responses and generated host bindings. No Lash database reset is needed. | This commit, FIG-7651 | Old JSON fails decoding, and the old v1 schema/declaration files are removed. There is no compatibility reader. |

The publication field has always described a newly prepared immutable artifact.
A settled request ID returns no new publication, as specified in
[FIG-7523](FIG-7523.md). The response carries neither an acceptance receipt nor
a replacement for the process event history.
