# FIG-7551: Transfer pooled connection ownership when beginning transactions

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `TransactionPrelude::begin_on(&mut PgConnection)` returned a borrowed transaction | Pass an owned `sqlx::pool::PoolConnection<Postgres>` instead. `begin_on` returns `Transaction<'static, Postgres>` and retains the checkout until BEGIN is acknowledged. Obtain the checkout with `pool.acquire().await?`; no new feature or policy opt-in is required. | This commit, FIG-7551 | Old calls fail to compile because a raw connection borrow cannot transfer the pooled owner. |
| A host's plain `pool.begin()` had SQLx's cancellation window before transaction depth was recorded | `lash::postgres::begin_unfenced(&pool).await?` preserves the connection's settings and uses the same completion owner as guarded transactions. It grants no writer fence. | This commit, FIG-7551 | A cancelled raw begin can leave a server transaction on a pooled connection; a later snapshot can fail with PostgreSQL SQLSTATE 25001. |

Lash's store and replay implementations use the shared owner automatically.
Stored formats, wire formats, transaction guards and refusal classifications
are unchanged. Detached migration, schema-observation and sweep sessions keep
owned connections that close on cancellation; their session locks never
return to a pool. No host reset is required.

Source: [transaction entry](../../../crates/lash-postgres-store/src/host/mod.rs)
and [completion owner](../../../crates/lash-postgres-store/src/postgres/guarded_tx.rs).
