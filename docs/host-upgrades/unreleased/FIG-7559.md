# FIG-7559: Explicit whole-request timeout policies

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `ProviderAttemptLimits::new(Duration, response_start, chunk_idle, max_attempts)` and `per_request() -> Duration` | Pass `RequestBound::Bounded(duration)` or `RequestBound::Unbounded`; `per_request()` returns `RequestBound`. Both response-start and chunk-idle bounds remain required, finite and validated. The recommended request bound remains 5 min. | This commit, FIG-7559 | Constructor or return-type compiler error. |
| `ProviderReliability::request_timeout: Option<u64>` and `request_timeout_ms(Option<u64>)`; null and zero inherited | `request_timeout: RequestTimeout` and `request_timeout(RequestTimeout)`. Choose `Inherit`, `Bounded(NonZeroU64)` in milliseconds, or `Unbounded`. Omission defaults to `Inherit`; null, numeric and zero values no longer decode. | This commit, FIG-7559 | Compiler or configuration decoder error. |
| No managed unbounded request policy | Set runtime `RequestBound::Unbounded`, then route `Inherit` or `Unbounded`. A finite runtime still refuses a route that exceeds its limit, including `Unbounded`. Start and idle timeouts and retry classification continue to apply. | This commit, FIG-7559 | `ProviderRouteAboveBudget` if an unbounded route uses a finite runtime. |
| `RouteBoundAboveBudget::route: u64` and `Copy` | The diagnostic's `route` is a `String`, including `unbounded`; use `Clone` when needed. | This commit, FIG-7559 | Compiler error in diagnostic consumers. |

For example, replace `"request_timeout":60000` with
`"request_timeout":{"policy":"bounded","milliseconds":60000}`. To disable
the request timer, use `"request_timeout":{"policy":"unbounded"}` and the
runtime policy above. Managed calls and durable redelivery still use the separate
recorded model-call deadline. Direct provider slot-delivery retention remains
finite, using the 30-day maximum when its request bound is unbounded. Finite
bounds retain the 30-day safety maximum. An unbounded request has no
request-specific maximum.
