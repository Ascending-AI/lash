# FIG-7580: Distinguish store commit identities from host operations

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `lash::persistence::OperationId` identifies a durable store commit. | Import `lash::persistence::CommitOperationId`. Its constructors, fields and stored representation are unchanged. `lash::OperationId` remains the host ingress identity. No new opt-in is required. | This commit, FIG-7580 | Unresolved import `lash::persistence::OperationId`. |
| `Processes::saved_reads` referenced the optional VM runtime in every feature selection. | Enable `codemode` to query saved kernel reads. The method and the saved-read fallback in `Processes::tool_call` now require that feature; ordinary retained tool calls remain readable without it. | This commit, FIG-7580 | Without `codemode`, calling `saved_reads` reports a missing method. Previously that feature selection failed to compile with unresolved `lash_vm_runtime` references. |

Source: [persistence exports](../../../crates/lash/src/persistence.rs).
The saved-read feature belongs to [the process facade](../../../crates/lash/src/process_admin.rs).
