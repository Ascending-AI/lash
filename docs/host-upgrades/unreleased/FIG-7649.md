# FIG-7649: Finish frame configuration before exposing a registry

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `FunctionRegistry::over_frame(bytes)` returned a readable, shareable registry that still accepted bindings. | Use `FrameRegistryBuilder::new(bytes)?`, configure plans, then consume it with `finish_declarations()` for admission or `finish_execution(positions, tables, supplied)?` for execution. The builder is exported by `lash::workflow::document` and `lash_kernel_doc`. No new opt-in is required. | This commit, FIG-7649 | The removed constructor fails to compile. |
| `FunctionRegistry::bind_frame_plans(positions, plans)` mutated a frame registry. | Call `FrameRegistryBuilder::bind_plans(positions, plans)` before finishing. | This commit, FIG-7649 | The removed method fails to compile; finished registries have no frame-binding methods. |
| `FunctionRegistry::bind_native_tables(positions, tables, supplied)` enabled execution before the registry was shared. | Pass those arguments to the consuming `FrameRegistryBuilder::finish_execution`. Missing native-only implementations still return `RegistryError::FrameNativeMissing`. | This commit, FIG-7649 | The removed method fails to compile; an unsuccessful finish exposes no registry. |

Release images, frame-position bytes and persisted documents keep their existing
formats. Hosts do not need to reset stored data.

Source: [frame construction](../../../crates/lash-kernel-doc/src/native_frame.rs)
and [facade exports](../../../crates/lash/src/workflow.rs).
