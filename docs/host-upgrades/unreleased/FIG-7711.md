## Retained documents and source across upgrades

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| A retained document can contain private bindings emitted by an older TypeScript lowering. Its printed source can lower to a different identity under a newer build. | Retained documents stay executable with their stored meaning. Printing and source-bearing publication are guaranteed only for documents lowered by the build performing those operations. A host retaining documents across an upgrade re-imports its own source, replaces the definition, and updates dependent document, link and source-map references. The identity may change. No new opt-in or migration is provided. | This commit, FIG-7711 | Printing an older document can return `Unprintable(ReadbackMismatch)`. Strict source-bearing publication of current source against the older document returns `WORKFLOW_SOURCE_MISMATCH`. |

The private-name set determines which bindings are reported and carried, so it
is part of the document's meaning. Equality remains exact. Store recreation
alone does not replace definitions, links or maps retained by a host outside the
store. Keep the host's original source for re-import; asking the new build to
print an old document is not an upgrade procedure.
