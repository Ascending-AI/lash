# FIG-7519: Read cell consumption beside its bound decision

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `ExecResponse`, committed `CellRecord` and `ExecCodeCompleted` and live `CodeBlockCompleted` named the result without consumption. | Each now requires `consumption: Vec<CellConsumption>`, with a typed resource, optional consumed and observed values, and limit. Initialize custom executor and record constructors with an empty vector. Time uses nanoseconds. Update stored-result readers and regenerate host bindings. No opt-in is required. | This commit, FIG-7519 | Missing-field compiler/decoder error, or no counters beside `CELL_BOUND_EXCEEDED`. |
| The closing cell span exported no bound consumption. | Read numeric `lash.cell.<resource>.{consumed,limit,observed}` for charges, CPU, wall and logical memory, plus `lash.cell.consumption`, a JSON array of the typed entries, on the existing `execute_tool <language>` span. Missing meter readings are null. Raw charge includes the refused crossing unit; consumed charge saturates at its limit. | This commit, FIG-7519 | A CPU and instruction limit near each other cannot be distinguished from host throughput changes. |
| Worker progress receipts carried CPU alone; recorded cell ends held no consumption snapshot. | Progress also carries the existing machine meters. Pair workers and parents from this revision. Reprovision stores when the changed durable format witnesses refuse preflight; pre-1.0 formats change in place without migrations. | This commit, FIG-7519 | Worker wire decode failure or durable format preflight refusal. |

| Low-level `WorkerMessage::Progress.work` was `Option<WorkerWork>`. | It is `Option<Box<WorkerWork>>`; box diagnostic work when constructing this low-level message. The wire representation of `work` is unchanged. Normal progress carries no diagnostic allocation. | This commit, FIG-7519 | A low-level Rust message constructor has the wrong `work` type. |
