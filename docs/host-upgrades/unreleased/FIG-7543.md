# Start observation feeds with `follow`

Hosts starting a session feed replace `snapshot().await?` followed by
`subscribe_and_recover(snapshot.cursor)` with one call that returns the
snapshot and its continuing stream together. No new opt-in is required.

```rust
use lash::FeedStart;

let (snapshot, mut feed) = session.observe().follow(FeedStart::Head).await?;
```

`ObservableSession::attach()` is removed. Replace it and the subsequent
subscription with `follow(FeedStart::Retained)` to replay retained language
observations, including completed cells. Commits already reflected in the
snapshot are skipped. Released evidence remains unavailable.

```rust
let (snapshot, mut feed) = session.observe().follow(FeedStart::Retained).await?;
```

Hosts starting a process feed replace the same snapshot/subscription pair
with `ObservableProcess::follow`. Its existing snapshot starts before
retained replay evidence, so its separate `ProcessFeedStart` type offers only
`Retained`.

```rust
use lash::process::ProcessFeedStart;

let observed = core.processes().observe(&process_id);
let (snapshot, mut feed) = observed.follow(ProcessFeedStart::Retained).await?;
```

Keep `snapshot()` for reads without a stream. Keep
`subscribe_and_recover(cursor)` to resume either feed from a persisted
cursor. Streams retain their existing error and gap recovery behavior.
Session `resume_from_cursor` and `subscribe_from_cursor` are unchanged.

Session `follow` acquires its notification watch before reading the initial
head and keeps that watch in the returned stream. If acquisition fails,
the stream yields `Err(EmbedError::Durable(cause))` once and ends with its
cursor unchanged, as `subscribe_and_recover` does. Handle the cause and
resubscribe from the last applied cursor, as described in FIG-7538.
