# FIG-7511: Incoming TypeScript integers are Numbers

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| FIG-7286 exposed kernel `Int` tool results and host inputs as TypeScript `bigint`, despite declaring integer fields as `number`. | Incoming integers are ordinary TypeScript `number`, including nested tool data, entry arguments and stored values. Arithmetic, strict equality, Math and JSON work as in JavaScript. Return strings for exact integers beyond the safe range. Explicit BigInt literals, constructors and `bigint` entry annotations keep exact semantics; outbound BigInts remain kernel `Int`. Python is unchanged. | This commit, FIG-7511 | Adapters expecting `typeof value === "bigint"` for ordinary incoming data must accept `"number"`. Integers above the safe range round to binary64 just as `JSON.parse` does. |

Generated integer declarations remain `number`. No opt-in or refusal is added.
Before 1.0 the internal representation changes in place, without a format version
or migration. Rebuild the host and its helper release together.
