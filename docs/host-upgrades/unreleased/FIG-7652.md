# FIG-7652: Kernel process engine state names its progress

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| A kernel process's engine state kept its last park (`parked`), that park's `requirements` and a `phase` of `running`, `parked` or `ended` as separate fields, so a cancelled, failed or timed-out process could still name its last park. | The state keeps one `progress`: `running` (the admitted `kernel_run` step and the park it resumes, absent before the first park) or `parked` (the run and the requirements its park recorded). An ended process has no engine state: its terminal transaction deletes it for every cause, as before. `KERNEL_PARKED_STATE_VERSION` now also guards this state and advances with this change. Reset the store or recreate in-flight kernel processes before deploying; no old-shape reader is provided. | This commit, FIG-7652 | Advancing, succeeding or surveying a process whose state is in the old shape fails as stored-data corruption: "the state is in the phase shape this build retired (FIG-7652)". |
