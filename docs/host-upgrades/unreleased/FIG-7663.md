# FIG-7663: saved callable publication requires printable source

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `HostArtifacts::publish_callable` could save executable callables whose source later refused to print | Publication materializes and prints in the authored dialect, verifying structural readback under default generated-source limits before retaining the definition. Handle materialization and source errors at publication. No new opt-in is required. | This commit, FIG-7663 | Unspellable tokens, missing authored dialects, over-limit source and readback mismatches refuse publication instead of failing only during `print_workflow`. |

`inspect_callable` still inspects executable reach independently of printing.
The `$lash_function` transport and the public signatures are unchanged.
Both dialects accept `callable.invoke(package.member, ...operands)` to spell
an exact linked call without source-call argument adaptation or snapshots.
TypeScript printing uses it when an ordinary call changes readback. Python
printing uses it for linked code calls. Existing retained definitions are not
rewritten by this change.
