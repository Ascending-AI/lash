# FIG-7552: Preserve native database error codes

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `StoreError::StorageFailure` and `StoreFault::StorageFailure` had only `backend` and `message` | Both add `code: Option<StorageCode>`, exported as `lash::persistence::StorageCode`. Add `code` when constructing them, or use `..` in field patterns. PostgreSQL carries `Postgres { sqlstate, class }`; SQLite carries `Sqlite { extended_code }`. No new opt-in is required. | This commit, FIG-7552 | Constructors and exhaustive field patterns fail to compile without the new field. |
| Durable `StoreFailure` carried only `kind` and `message` | Its optional `code` preserves native database codes through graph and artifact conversions. Custom store implementations use `None` when no database supplied a code. | This commit, FIG-7552 | Existing struct literals need the new `code` field. |
| Graph and durable conversions flattened database failures into `Backend` faults | Failures carrying a native code now retain `StorageFailure` and its backend-specific code through these conversions. Existing runtime error codes and contention rules are unchanged. | This commit, FIG-7552 | A host that only logs a `Backend` variant must also handle `StorageFailure`. |
| `RuntimeSessionState` phase-preparation methods named a type with no facade path since `96424c6d5a8dacae65fca8ca5bb25be0424eb1d5` | Use `lash::persistence::PhaseContentPreparations` and its method argument `lash::persistence::PreparationRole`. Each has this one canonical home; no new opt-in is required. | Separate facade repair in this landing, FIG-7552 | Hosts could not name the getter result or setter argument through `lash` alone, and facade completeness failed. |
| Serialized storage faults omitted the database code | Faults now serialize `code`, with a backend-tagged object or `null`. Update strict decoders and retained fault schemas in place. | This commit, FIG-7552 | A strict old decoder may reject the added field. |

A PostgreSQL fault now includes
`"code":{"backend":"postgres","sqlstate":"25001","class":"25"}`.
A SQLite UNIQUE violation includes
`"code":{"backend":"sqlite","extended_code":2067}`.
Pool, I/O and decode failures without a database code use `null`.
The existing `backend` and `message` fields and display text remain available.

Hosts may log the full SQLSTATE or classify its two-character class, including
`40` for transaction rollback, `08` for connection exceptions and `25` for
invalid transaction state. Classify using the typed code, never message text.
The database code is distinct from Lash's runtime error code. Existing
contention mapping and retry policy are unchanged; a class alone does not
prove that retrying an operation is safe.
