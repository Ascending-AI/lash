# FIG-7600: Registered callee identities are read without materializing a set

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `RegisteredFunction::callees(&self) -> &BTreeSet<FunctionId>` | `RegisteredFunction::callees(&self) -> impl ExactSizeIterator<Item = FunctionId> + '_`. Consume owned identities directly: replace `.callees().iter().copied()` with `.callees()`. Collect explicitly when an owned or mutable set is needed. Identities remain unique and ascending. No wire or stored-state reset, feature opt-in, or dependency-floor change is required. | This commit, FIG-7600 | Rust callers using `.iter()` on the returned value no longer compile; loop bodies that dereference a callee must use its owned identity instead, and lookups expecting a reference must borrow it. |
