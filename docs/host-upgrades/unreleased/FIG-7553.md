# FIG-7553: Retain model stream transport evidence

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| A stream timeout could lose a successful HTTP status; only pod logs described partial output. | Read `LlmTransportError.stream_evidence` and the sealed attempt's `NormalizedError.stream_evidence`. `ModelStreamEvidence` carries optional status, response-header and first-body-chunk times, bytes received, protocol position and an ordered `PartialOutputKind` set. Custom `NormalizedError` constructors initialize `stream_evidence: None`. | This commit, FIG-7553 | Missing-field compiler error in custom constructors, or a timeout trace cannot distinguish waiting for headers from a stalled response body. |
| The logical model-call span omitted transport progress. | On failure, read `http.response.status_code`, `lash.model.response_headers_ms`, `lash.model.first_body_chunk_ms`, `lash.model.bytes_received`, `lash.model.protocol_position` and `lash.model.partial_output` on the existing model span. Failed attempt spans carry the same fields. No content consent or new configuration is needed. | This commit, FIG-7553 | Status 200 and `other_event` show that the provider responded even when no text or reasoning delta reached the host. |

All three HTTP provider drivers fill the shared evidence. OpenAI Responses
and Chat Completions both participate. Times are monotonic milliseconds since
send, using the injected clock. Missing observations remain absent; an actual
zero duration remains zero. Byte counts include SSE framing and count the
bytes delivered by the HTTP body before decoding. The bounded kind set is
ordered as text, reasoning, tool arguments, other event. An empty set means no
protocol event was observed. No body, prompt or error prose enters these fields.

The existing retry protocol-position predicate and charge-safety policy are
unchanged. Custom provider implementations may leave evidence absent.
