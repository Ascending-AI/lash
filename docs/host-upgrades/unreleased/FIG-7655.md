# FIG-7655: Terminal process transitions return no state

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `ProcessEngine::advance` returned `(EngineState, EngineAction)`, including a state beside `EngineAction::Terminal`. | Return `EngineTransition::Continue { state, action }` for continuing work and `EngineTransition::Terminal(outcome)` to end the process. `EngineAction::Terminal` is removed. The new enum is exported at `lash::plugins::EngineTransition`. | This commit, FIG-7655 | Engine implementations and hosts using the previous tuple or terminal action fail to compile. |

Hosts that implement process engines must update `advance` and stop constructing
or encoding state on terminal paths. Hosts that drive the engine contract must
match the transition before validating, projecting or persisting next state.
Terminal handling commits the outcome and deletes the previous state.

Persisted state, process outcomes and format stamps are unchanged. Existing
stores need no reset for this change.

and [transition result](../../../crates/lash-execution-contracts/src/process/engine_state.rs).
