# FIG-7506: Store synced checkpoint environments by content reference

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| `SavedTurn.checkpoint.environment` holds an inline `SyncedEnvironment`, for example `{"protocol_iteration":0,"sync":{"tool_specs":[]}}`. | The field holds a content digest, for example `"<digest>"`; `SavedTurn.content["<digest>"]` holds the serialized environment. Hosts serializing `SavedTurn` keep this blob with its other checkpoint content and use matching readers and writers. No new feature, configuration or policy opt-in is required. | This commit, FIG-7506 | An old inline environment is refused as an invalid content-reference string. Omitting the referenced blob produces `TurnCheckpointRestoreError::MissingContent`. |
| `RecordedRequestTemplate::of_retained_request` places `tools` after `messages` in its canonical JSON literals. | Immutable configuration fields, including `tools`, precede `messages`; the changing `scope` follows it. JSON values and batch outcome types remain unchanged. Hosts comparing exact retained canonical request bytes must use the new field order. Recorded bodies retain their own bytes and remain readable. No opt-in is required. | This commit, FIG-7506 | Comparing newly lowered bytes against the previous literal field order reports a different body digest. |
