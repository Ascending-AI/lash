# FIG-7530: Failed-cell results and whole call identities

| Old contract | New contract / host action | Commit and ticket | Missed-change diagnostic or symptom |
| --- | --- | --- | --- |
| Failed-cell output preceded the error; `completed_calls` also contained failures | The error leads, then separate `completed_calls` and `failed_calls`, then output and bindings. No opt-in is needed. | This commit, FIG-7530 | A repair request obscures the original error or treats a rejected call as completed. |
| `CallResultSummary.text` was a JSON byte prefix | The same `text` and `truncated` fields carry a structural preview with whole scalar values and explicit elisions. Treat it as presentation text. | This commit, FIG-7530 | A prefix is mistaken for a complete identifier, or preview text is parsed as a tool result. |
| Row/byte overflow reported counts alone | The final notice names omitted completed calls by operation and ID, or counts them with whole earliest/latest IDs. No opt-in is needed. | This commit, FIG-7530 | Completed writes disappear from repair context. |
| `CallFeedbackPolicy::new(0, 0)` was valid | Blocks must meet `CallFeedbackPolicy::MIN_BLOCK_BYTES`. Handle `BlockBelowMinimum`; recreate persisted sessions below the floor. Zero result bytes remain valid. `ToolCallId::ENCODED_BYTES` derives the ID allowance from its format. | This commit, FIG-7530 | Constructor/deserializer refuses a block below the minimum; exhaustive matches need the new error variant. |

Failed RLM cell results now begin with the failure, followed by completed
calls, failed/interrupted calls and repair guidance, then prints, images and
bindings. Live requests and durable replay use the same renderer.

`CallResultSummary` keeps its `text` and `truncated` fields. The text is a
structural preview rather than a JSON byte prefix. Whole scalar leaves stay
intact; long strings carry a character count in place of their contents;
arrays and objects report elided member counts. Preview text may contain
elision notation and must not be parsed as a complete tool result.

The calls listing reports omitted completed calls by whole operation and
call ID, or by count and whole earliest/latest IDs if the names cannot fit.
`CallFeedbackPolicy::new` now rejects blocks below `MIN_BLOCK_BYTES` with
`BlockBelowMinimum`, including through deserialization. The minimum is
321 bytes on 64-bit hosts, derived from maximum counts, the listing
framing and Lash's fixed call-ID format. A zero result budget remains valid
and omits result previews. Standard 512-byte / 16-KiB limits are unchanged.
Persisted sessions with a custom block below the minimum must be recreated
before they can be used with this reader.

Full results remain in the existing call ledger. Hosts can read them with
`DurableSession::read_tool_call` or `read_cell_tool_calls`. There is no
built-in model-callable lookup by call ID, so the omission notice does not
advertise one. Classification uses recorded outcomes only.
