# Bounded owner mailbox reads

Hosts implementing `DurableStore` add `max_mail_bytes: u64` to `begin` and
`open_process`, and implement `revalidate(actor, epoch, expected)` as a keyed,
read-only ownership and revision check. Forward the byte budget through store
decorators. The runtime supplies its existing owner read budget; no opt-in is
required. Old implementations and calls fail to compile.

Cold and retained opens now deliver a byte-bounded prefix with at most
`OpenedActor::MAIL_PAGE_ROWS` candidate messages. `seen` is the acknowledgement
frontier of that prefix. Later messages and wake positions remain pending.
An empty-body message can fit a zero-byte page; authority-only reads use
`revalidate` and grant no acknowledgement frontier.

Hosts constructing `OpenedActor` supply `close_requested` from pending session
close mail independently of the page, in the same snapshot as ownership.
`ActorTx::close_requested()` exposes this fact. A close beyond the page must
not be acknowledged through the page's frontier.

Ticket: FIG-7566. The landing commit records the change.

Hosts constructing `RunnerConfig` also supply `graph_reads` from the same
`DurableConfig::settings()` used for the node. `RunnerConfig::new` carries it
automatically. This keeps runner and actor-context cold reads on that policy.
