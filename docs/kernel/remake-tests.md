# Semantic laws still owed by the bytecode core

FIG-6689 and FIG-6690 removed the tests that pinned the retired execution
representation and listed, row by row, the semantic property each one should be
remade to pin through the new engine. FIG-6710 and the bytecode-core switch
(FIG-7694, with the deleted-law classification of FIG-7692) removed more. This
page keeps only the remakes that are still owed on main.

A row left the ledger when either:

- **Done.** A law on main pins the property, and its target runs it. Examples:
  the cold point read (`lash-kernel-vm` `laws::large`), corpus cross-resume
  after every statement (`lash-kernel-conformance`
  `tests::corpus_cross_resumes_after_every_statement`), the thousand-way fan-out
  (`laws::pause::a_thousand_way_fan_out_delivered_one_per_cold_reopen_joins_every_child_once`),
  the continuation refusal and resume laws (`laws::continuation`), and the
  plan-independence laws (`laws::layout`).
- **Moot.** The row's subject was a retired mechanism and it named no semantic
  property beyond laws that survive. That covers the census, residency, page
  publication, op-stream verifier, register allocator, frozen family,
  `TextCursor` and record-hint rows; the allocation and page-count budgets
  (performance measures, not laws); and exact memory refusal thresholds across
  plans, which are deliberately retired (`K-BND-003` is a conservative bound).

Each row below names the removed test it came from, so its old input and oracle
can be recovered from history. Write a remake against `Program`/`KernelMachine`
or the embedding API, never against the engine's internals, and only where it
is the single law catching a real bug.
