# TypeScript dialect: deviation register

Where the TypeScript dialect of the lash kernel knowingly behaves differently from ECMAScript as Node runs it. Each row names the law that pins the dialect's behaviour; a row is removed only with the difference. A Test262 case that fails for a reason listed here cites the row's code.

How asynchronous source maps to kernel tasks is described in `src/lower/async_fn.rs` and `src/helpers/promise.kernel`. The Node witnesses are in `witness/async/`.

## Types

The `TS_TYPED_*` rows are every place where trusting a type changes behaviour. The front end believes an annotation (on a variable, a parameter, a return type, an array's elements, an object type's property, an `as` assertion) and a tool's declared result type, and does not check them; `src/types/mod.rs` says what it believes and what it proves. A value is mistyped when it reaches an annotated place through `any`, or as an argument the caller left out. `any`, `unknown` and code with no annotation are never trusted and keep JavaScript's behaviour: each row's law runs its program a second time with the annotations written `any` and gets JavaScript's answer.

## Test262 exclusions

Test262 is the oracle for the untyped language (`tests/test262_kernel.rs`). A test that main's record marks as passing and that the kernel does not pass is a regression unless a row here names it and cites the code of the row above that is its grounds. The runner refuses an unregistered one, a row that names no recorded pass, and a row whose code is not in the register.
