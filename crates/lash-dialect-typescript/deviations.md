# TypeScript dialect: deviation register

Where the TypeScript dialect of the lash kernel knowingly behaves differently from ECMAScript as Node runs it. Each row names the law that pins the dialect's behaviour; a row is removed only with the difference. A Test262 case that fails for a reason listed here cites the row's code.

How asynchronous source maps to kernel tasks is described in `src/lower/async_fn.rs` and `src/helpers/promise.kernel`. The Node witnesses are in `witness/async/`.

| Code | ECMAScript, in Node | The dialect | Why | Law |
| --- | --- | --- | --- | --- |
| `TS_RUN_END_STRICT` | A cell that ends while a promise is still pending keeps the process alive until everything has settled. | The run ends when the cell ends. A task still running then makes the end the typed error `TasksOutstanding` (`K-TASK-018`), except a member of an aggregate the cell has already awaited past (a race's loser, the rest of a failed `Promise.all`), which is cancelled without cleanup. Where the front end can see it, a discarded tool call (`tool(x);`, `void tool(x);`) is refused at lowering with `TS_UNAWAITED_TOOL`. | Sam's ruling (kernel spec §1): a run that ends with an unjoined task is an error. | `tests::async_fn::a_cell_that_ends_with_a_running_task_is_an_error`, `a_discarded_tool_call_is_refused` |
| `TS_UNHANDLED_REJECTION` | A rejection with no handler when the microtask queue drains ends the process, even if a handler would have been attached after a later arrival. | A rejection is unhandled only if nothing has awaited the promise, chained from it or aggregated it by the time the cell ends; the end is then `TasksOutstanding`, naming the task. A handler attached late, after any number of arrivals, handles it. | A task's error is data on its handle (`K-TASK-016`); the kernel has no macrotask boundary to judge at. | `tests::async_fn::a_rejection_is_unhandled_only_at_the_cells_end` |
| `TS_JOIN_WAKE_ORDER` | A promise's reactions run in the order they were registered. | When a promise settles, tasks that await it directly continue before aggregates (`Promise.all`, `allSettled`, `race`, `any`) that hold it, whichever registered first (`K-TASK-008`). The orders agree unless one promise is both awaited directly and held by an aggregate registered earlier, and both continuations write shared state. | The kernel wakes single joins before list joins. One more kernel rule (wake in the order the joins began, whatever their form) would remove this row. | `tests::async_fn::a_single_waiter_wakes_before_a_list_waiter_registered_earlier` |
| `TS_PROMISE_RACE_EMPTY` | `Promise.race([])` never settles. | It rejects with the kernel error `empty_join` (`K-TASK-013`). | A task that can never end would make every cell that holds one end in `TasksOutstanding` or `Deadlock`. | `tests::async_fn::a_race_of_nothing_rejects` |
| `TS_AWAIT_THENABLE` | `await` of an object with a `then` method calls it, and so do `Promise.resolve` and a promise resolved with one. | Only a promise the dialect made is awaited; any other object is its own value. | A promise is settled by a task's end, and a foreign `then` would need a task that a callback can end. `new Promise(executor)` is refused for the same reason (`TS_NEW_UNSUPPORTED`). | `tests::async_fn::a_thenable_is_a_plain_value`, `the_promise_constructor_is_refused` |
